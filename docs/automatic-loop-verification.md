## Reusable additions

- `recover-il2cpp` routes by metadata version, executes a configured trusted compatible analyzer and retains execution/dependency/config hashes plus fresh output. Framework-dependent isolation avoids the observed trimmed app-local System.Collections type-forwarding failure. The repository exporter leaves unknown provider file offsets null; the ELF mapper derives actual offsets, rather than accepting the old exporter's erroneous zeros.
- `android-scenario` selects an exact authorized device/app, optionally installs selected APKs, compares installed source hashes and validates the foreground package before normal input/capture. Failed execution remains separate from parity assertions.
- `compare-ui-values` accepts immutable PNG/JPEG captures, reviewed regions, expected values and confidence. It preserves crops/TSV, rejects transparent selected pixels, and returns inconclusive for ambiguous recognition. CUA's native captures were JPEG960×596; Android captures were PNG2400×1080. Original bytes remain intact, including early captures with misleading `.png` filenames; correctly named JPEG copies have identical hashes.
- Local build scripts compile the owned LibCpp2IL exporter and Android touch DEX against explicitly selected installed tools, retaining build manifests. Game and external analyzer binaries are excluded from the npm package.
- The feature workflow tells the host agent to connect fresh maps, target adaptation, actual inputs and compared checkpoints, retaining distinct evidence and human-acceptance states.

The outlined source font was initially inconclusive under ordinary OCR. An explicit luminance230 bright-text mask on source regions produced black text on white; the crop, parameter and original hash remain recorded. No expected value or digit whitelist was passed to OCR, and confidence was not lowered. The visible complete `+75` word is retained and normalized as the integer75. Earlier inconclusive/error reports remain available.

## Repeat the supported stages

Use a supported Node release and build the repository. Install the optional parser environment from requirements-unity.txt. Prepare a trusted LibCpp2IL runtime and compatible full .NET host; the execution report distinguishes its observed library identity from a caller-supplied label.

```bash
npm run build
node scripts/build-libcpp2il-indexer.mjs \
  --lib /absolute/LibCpp2IL-runtime \
  --dotnet /absolute/dotnet \
  --compiler /absolute/sdk/Roslyn/bincore/csc.dll \
  --framework /absolute/shared/Microsoft.NETCore.App/10.0.12 \
  --out /absolute/NEW-indexer
export REA_UNITY_LIBCPP2IL_INDEXER=/absolute/NEW-indexer/ReaIl2CppIndexer.dll
export REA_UNITY_DOTNET=/absolute/dotnet
export REA_UNITY_PYTHON="$PWD/.tools/python/bin/python"
node scripts/verify-real-apk.mjs /absolute/apk-splits fresh /absolute/NEW-case
```

That driver intentionally selects this game's ARM64 currency methods and CoinPill root. Other features require REA investigation and a new reviewed case; the script must not silently substitute this example. Use the fresh map with verify-pending-coins-native.py and optional installed Capstone, then feature-transfer-example.mjs to stage this example into a new project. Actual Editor import, PlayMode and BuildTransferredPlayer.Build produce the target Player.

For source execution, select an owned authorized device and actual observed resolution, then call the shared operation:

```bash
export REA_UNITY_ADB=/absolute/sdk/platform-tools/adb
node scripts/build-android-touch.mjs /absolute/sdk /absolute/jdk /absolute/NEW-touch
export REA_UNITY_TOUCH_DEX=/absolute/NEW-touch/classes.dex
node dist/cli.js unity android-scenario --workspace /absolute/work --file reviewed-source-case.json
```

The case JSON is the operation's `record`, without a wrapping record property. It supplies caseId, serial, package, width, height, original workspace APK paths and reviewed actions. Multi-touch currently uses SDK platform35/build-tools35.0.1. Device state, match rewards and timings vary; observe each run and define its actual expected outcome rather than forcing75.

The host's approved Unity/player tools execute target input and capture the resulting windows. The macOS test helper requires explicitly authorized system events plus OS permission; it checks the exact app, PID and uniquely named main window before every bounded click. Permission denial sends no events. It is not used to grant itself permissions.

```bash
export REA_UNITY_TESSERACT=/absolute/tesseract
node scripts/compare-feature-checkpoints.mjs reviewed-checkpoints.json NEW-results.json
```

The checkpoint specification contains `workspace` and1–20 operation records in `checkpoints`. The driver returns a nonzero exit for mismatched/inconclusive checks and retains each shared-operation report. Captures/action evidence and target build identity remain separately linked by the host's case record.

This case demonstrates an agent-operated, tool-backed workflow for the pending-coin behavior. No human acceptance was inferred from permission grants or automated checks.
