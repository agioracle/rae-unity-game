# Unity feature investigation and transfer

The edition retains the complete REA CLI/MCP runtime. These additions supply Unity evidence and integration boundaries; the host agent uses REA to reason about code and writes the target implementation.

| Operation (`unity_` + underscores in MCP) | Input and result |
| --- | --- |
| `recover-il2cpp` | Selected binary/metadata, toolVersion (≤80 characters), provider auto/il2cppdumper/libcpp2il and exact observed unityVersion for LibCpp2IL. Metadata35+ routes to a compatible trusted `REA_UNITY_LIBCPP2IL_INDEXER`; older inputs can use `REA_UNITY_IL2CPP_DUMPER`. Managed indexers run through `REA_UNITY_DOTNET` with isolated dependencies. Retains fresh output, hashes and failed execution reports. |
| `map-il2cpp` | Workspace-relative binary, metadata, map and provenance; format `il2cppdumper-script` or `libcpp2il-jsonl`; optional query/assembly and paging. Checks source hashes and ELF-backed addresses; preserves ambiguous/shared/absent pointers. |
| `unpack-bundle` | One workspace-relative UnityFS 6–8 file; exact member bytes in a new evidence directory, hashes and source linkage. |
| `trace-references` | Explicit `paths` array, root `path` and decimal-string `pathId`; outgoing PPtr closure with field paths, cycles, unresolved externals and depth/node limits. |
| `inspect-target` | Absolute target project; actual version, packages, input, rendering, assemblies, script conventions, GUID inventory and context fingerprint. |
| `plan-transfer` | `record` with targetProject, featureId, source-backed claimIds, staged files, adaptation decisions and validation cases; hashes and new target GUID assignments. |
| `android-scenario` | Reviewed caseId, exact serial/package/resolution, optional workspace APK paths and install flag, 1–20 capture/tap/hold/wait actions. Hashes installed APKs, guards foreground identity, and retains binary PNG frames plus input outcomes. Does not assert gameplay. |
| `compare-ui-values` | Reviewed source/target capture path + sha256 + ROI + scale, optional lightTextThreshold, expected signed integer and minimumConfidence ≥80 (default85). Bounded PNG/JPEG crop and Tesseract TSV; returns passed/mismatch/inconclusive for one numeric value only. |
| `apply-transfer` | Exact workspace-relative plan and its SHA-256; rechecks evidence/context and creates one new `Assets/<featureId>` folder. Does not compile or establish parity. |

CLI: `rea-unity-game unity <operation> --help` lists input fields. Array options accept JSON, for example `--paths '["recovered/.../level2","recovered/.../sharedassets2.assets"]'`; numeric depth/node/page options are numbers. `plan-transfer` uses `--workspace /work --file transfer-request.json`; the file contains the `record`, without a wrapping `record` property.

## IL2CPP addresses

Il2CppDumper's [script schema](https://github.com/Perfare/Il2CppDumper/blob/master/Il2CppDumper/Outputs/ScriptJson.cs) supplies `ScriptMethod` addresses/names/signatures. Its [generator](https://github.com/Perfare/Il2CppDumper/blob/master/Il2CppDumper/Outputs/StructGenerator.cs) calls `GetRVA`; for an [on-disk ELF](https://github.com/Perfare/Il2CppDumper/blob/master/Il2CppDumper/ExecutableFormats/Elf.cs), this returns the ELF virtual address. This adapter supports on-disk little-endian ELF32/ELF64 ARM, ARM64, x86 and x86_64. Memory dumps, PE and Mach-O need their own adapters; do not feed their addresses to this mapper.

Provenance JSON is `{ "provider": "name", "version": "exact version/commit", "binary_sha256": "...", "metadata_sha256": "..." }`. These are attributed generator claims: matching hashes do not independently prove the metadata/code association. LibCpp2IL JSONL uses the practice index fields `assembly`, `token`, `full_name`, `signature`, `virtual_address`, `rva`, `file_offset`, `has_native_pointer`; the last file offset is independently checked against ELF segments. Assembly qualifies tokens; shared addresses preserve all aliases.

`elf_va`, `provider_reported_rva`, `file_offset` and `image_relative_address` remain separate. The last means VA minus the lowest PT_LOAD VA; it need not match the provider's convention. `runtimeBase` means the observed runtime address corresponding to that lowest PT_LOAD VA, so `runtime_va = runtimeBase + image_relative_address`. Never supply a guessed base. ARM Thumb pointers preserve the original low bit and return the normalized instruction address separately. Use core `open_binary` and `procedure_pseudo_code`/`procedure_assembly`; inspect their schemas and provider coordinate rules. Ghidra also supports explicit `file-offset:0x...` selectors.

Configure only a trusted local analyzer. The executable hash and invocation are retained; managed plugin dependencies and generated runtime configuration are hashed; the caller version label and complete OS/framework environment are not independently attested. The repository exporter also records the observed LibCpp2IL informational version. Configure the analyzer's documented unattended mode before using a stdio tool; nonzero exits leave incomplete output and are not accepted as a successful map. Metadata compatibility is analyzer-specific. No dummy DLL is treated as recovered C# method bodies.

## Resource boundaries

[UnityPy PPtr semantics](https://github.com/K0lb3/UnityPy/blob/master/UnityPy/classes/PPtr.py) distinguish local fileID 0 and external table index `fileID - 1`. This tool only reads explicitly admitted files. External names resolve by a unique case-insensitive admitted basename; collisions remain ambiguous, not silently selected. PPtr-shaped fields are structural references, not runtime selection evidence. PathID is a decimal string qualified by source path/hash; it is never an editable project GUID/fileID.

UnityFS preflight caps input and expanded data at 512 MiB, metadata at 16 MiB, block sizes at 32 MiB, members/blocks at 10,000 and block expansion at 512×. Bounded LZMA and pinned UnityPy-environment LZ4 are supported. Encryption and unknown formats fail. Single SerializedFiles default to 64 MiB; explicit `maxInputMiB` admits 1–128 MiB for object/component/reference operations and investigation roots. The limit is checked before parsing; graph sets admit at most 32 files/256 MiB, 500 visited nodes and 2,000 edges. TypeTree errors, missing files, depth/edge/node limits produce partial results. Pinned decoding disables bulk native allocation and enforces limits before vector/class expansion (100,000 values per object, 500,000 per process, depth 128), including automatic AssetBundle parsing; oversized TypeTree metadata is rejected. Dynamic Resources/Addressables/string/code references require additional REA investigation.

## Target adaptation

The host authors namespace, input, rendering and lifecycle decisions against the inspected target. Source files must already be staged inside the evidence workspace and be associated with hashed claims. Plan/apply do not generate gameplay from a question themselves.

Each file uses `{ "source": "reports/staged/Foo.cs", "target": "Foo.cs", "sourceGuid": "optional-old-editable-guid" }`. New GUIDs are assigned; textual serialized GUID references are remapped or must identify a unique existing target asset/built-in resource. Exported built-player PathIDs are never copied as project GUIDs. Binary media can be staged, but opaque binary serialized Unity assets are not supported by this text/known-media transfer path. Metadata/import fidelity still requires Unity Editor inspection.

Application exclusively creates a new feature folder, never overwrites an existing folder or feature `.meta`. Failure after ownership acquisition leaves `.rea-transfer-incomplete` for inspection, without deleting potentially concurrent user edits. Orphan `.meta` files are reported separately and cannot satisfy GUID dependencies. Context fingerprints hash supported text/settings/meta and use size/mtime for other assets; Library/UserSettings are excluded. Budgets and symlink checks can reject very large or linked projects. After import, verify actual assemblies, prefab/scene references, normal input, repeat and lifecycle behavior in the target Editor and record actual artifacts. Reported tests and explicit human acceptance remain separate.


## Runtime observations

Configure `REA_UNITY_ADB` as an absolute trusted ADB executable. A reviewed Android case selects one serial and package, up to16 APKs, at most20 actions, 60 seconds of requested holds/waits and a 120-second loop budget (bounded individual ADB operations and cleanup can add time). Each hold is ≤10 seconds and ≤5 pointers. Multi-touch requires a locally built repository `ReaTouch` DEX selected by `REA_UNITY_TOUCH_DEX`; it uses Android shell InputManager, without modifying the APK. API35 was exercised; other device/OS combinations require validation. APK installation runs only with explicit `install:true`. When intake has native-library directory evidence for the selected APK hashes, the shared owner intersects their ABIs and checks the selected device's `ro.product.cpu.abilist` before installation. `ABI_MISMATCH` retains a blocked report and sends no install or input. Declared ABI compatibility alone does not prove native execution. Package/foreground and original hashes are checked before case input. PNG captures are limited to16MiB/16Mpx and validated for framing, CRC and bounded scanline decompression. Missing capabilities fail explicitly.

Numeric comparison uses the configured Python/Pillow environment and absolute `REA_UNITY_TESSERACT`. Both captures and explicit regions are hashed, byte/pixel/frame/scale budgets precede decoding, and selected transparent pixels are rejected. Optional bright-text thresholding is recorded; expected values are never passed to OCR. One complete numeric OCR word with sufficient confidence is required. Original captures remain untouched. Retained raw TSV, prepared crop, helper/runtime identity and OCR executable/version support inspection; this is an observable numeric check, not a complete renderer comparison or internal-state proof.

The macOS `native-tools/player-clicks.swift` helper is an optional reviewed test utility. It requires user-authorized system events and existing macOS PostEvent permission, an exact owned app path, unique matching frontmost process/main window and bounded coordinates/count. It never grants OS permissions automatically. Window-server movement precedes down/up to avoid stale Unity mouse coordinates. Obtain target captures through the host's approved screenshot tools.

## General feature investigation (0.5)

`investigate-feature --workspace /work --file reviewed-investigation.json` accepts `caseId`, `question`, optional `targetProject`, `native` and `bundles`. It selects source snapshots or extracted artifacts by a unique relative `suffix` and optional SHA-256; multiple ABIs require explicit selection. `native` contains `binary`, `metadata`, `query`, optional `assembly`, and either `mode:"recover"` with exact `unityVersion`, `toolVersion`, optional `provider`, or `mode:"catalog"` with attributed `map`, `provenance` and `format`. Optional bundles select an artifact, admitted member names and exact path/PathID roots. No game names, currency classes, default ABI or object IDs are built into this workflow. Its `semantic_status:"requires_host_investigation"` means the host must still interpret evidence and implement the requested feature.

`inspect-native --workspace /work --file reviewed-native.json` takes `caseId`, hashed `map`/`mapSha256`, 1–32 explicit `{assembly,token}` methods and `maxBytes` (4–16384 per method). Requires Capstone5.0.6 in the configured Python environment. It independently derives executable file offsets from ELF64 little-endian ARM64 or ELF32 ARM segments. ARM32 uses the provider pointer low bit for ARM versus Thumb mode, preserves `provider_address`, and reports a separate normalized instruction address. Windows end at the next unique catalog pointer, with an aggregate64KiB code limit and4MiB conservative output budget before alias serialization. Shared entry/callee aliases are retained. Navigation windows are neither independently proven method sizes nor original C# bodies. Unsupported architectures fail explicitly.

`decode-component --workspace /work --file reviewed-component.json` takes `caseId`, SerializedFile `path`/`pathId`, explicitly selected MonoScript `scriptPath`/`scriptPathId`, `schema`/`schemaSha256`, and `map`/`mapSha256`. Checks schema attribution against all four mapped source hashes, MonoScript assembly/type, Unity version, original native m_Script header and full object byte consumption. Generated fields remain derived from an external schema; input association alone does not prove its layout. `scripts/generate-component-schema.py --help` generates a create-only attributed schema from metadata-only navigation DLLs using optional trusted TypeTreeGeneratorAPI0.0.10. It records every library hash and does not execute game DLLs. Select the required serialization dependencies explicitly (1–128 DLLs, 64 MiB per DLL, 256 MiB total); a larger metadata-only export is not automatically admitted. The pinned provider's distinctive `List<string>` container shape is normalized to `vector`; scalar strings are preserved and the raw node hash plus each normalization are recorded. Keep any historical/manual annotations explicit. No DLLs or analyzer binaries ship in this package.

`compare-ui-signals --workspace /work --file reviewed-signals.json` takes `caseId`, caller-labelled `state` and independent source/target `{path,sha256,roi,rgb:{min,max},fraction:{min,max}}`. It compares visible RGB proportions in bounded opaque PNG/JPEG crops and retains hashes, producer and pixel counts. Calibrate colors from a labelled baseline before evaluation; Unity linear GUI colors and captured display RGB can differ. A matching color region does not establish an internal state, action, artwork match or whole-feature parity.

Android actions also admit `{kind:"wait-until",signal:{roi,rgb,fraction},timeoutMs,pollMs}`. A late matching capture cannot authorize later input: capture and measurement use the remaining deadline and a final clock check. Timeouts remain failed cases. Requested waits/holds/deadlines total at most60 seconds; captures total at most64 frames/128MiB. Guards use caller-reviewed visual predicates, not a general scene recognizer.

Public drivers use reviewed JSON rather than executable case hooks:

- `node scripts/verify-real-apk.mjs reviewed-spec.json /absolute/NEW-output`: `{input,authorization,investigation}`; intake and shared investigation only.
- `node scripts/apply-feature-transfer.mjs reviewed-transfer.json NEW-result.json`: `{workspace,claims,transfer}`. `claims:[]` can reference existing claim IDs. Reserves a create-only receipt before changing the workspace/target; failures retain a receipt.
- `node scripts/compare-feature-checkpoints.mjs reviewed-checkpoints.json NEW-result.json`: `{workspace,checkpoints}`. Existing plain numeric records remain supported; use `{operation:"compare-ui-signals",record:{...}}` for color predicates, or `compare-ui-values` for explicit numeric dispatch.

The host agent discovers source behavior, stages code against the inspected target, invokes Editor/build/input tools, and links their actual results. These drivers do not contain a game-specific feature generator. Historical currency reproduction drivers now live under `examples/pending-coins/`; they are optional case material. The new lifecycle case and its boundaries are in [general feature verification](general-feature-loop-verification.md).

For an IL2CPP player without serialization schemas, the host can use a trusted compatible Cpp2IL to generate fresh metadata-only libraries before schema generation. The exercised provider was Cpp2IL2022.1.0+b5ad444b82267cb1e4b88b8b373c008105bdea52 with metadata39. Run it in a new owned working directory, with explicit binary/metadata/version paths, `--use-processor attributeanalyzer --output-as dll_empty --output-to NEW_DIRECTORY`. Record the provider/runtime hashes, exact argv, input hashes, retained log and all output-library hashes. This analyzes attributes and creates empty method bodies; it does not run game DLLs or recover original bodies. Feed that directory to `generate-component-schema.py`, then hash-bind and decode through `decode-component`. The TypeTreeGeneratorAPI direct-IL2CPP entrypoint was present but failed on this case; its presence did not establish compatibility. Failures must remain visible, and unsupported inputs must not be silently replaced with a historical schema.


## Fresh ARM32 package coverage (2026-10-20)

`build-libcpp2il-indexer.mjs` now packages a bounded registration fallback. If the provider found metadata registration but rejected several raw references to its module array, the fallback uses the metadata module count before testing uniqueness. It accepts exactly one provider-validated candidate with a complete, unique module-name match. Genuine ambiguity fails. Search limits remain 512 MiB binary, 4,096 modules, 64 anchors, 16,384 xrefs and 262,144 possible table starts. This is pointer navigation, not original method-body recovery.

When the selected trusted library directory contains `Cpp2IL.dll` and `Cpp2IL.Core.dll`, the builder also emits its framework runtime configuration and a hashed `Plugins/ReaRegistrationPlugin.dll`. Run that frontend with the **new tool output directory as its working directory**. This keeps it away from bundled conflicting `System.*`/`Microsoft.*` assemblies and makes trusted plugin discovery explicit. The build manifest records sources, output, compiler, framework references, plugin and copied dependencies. Do not run this frontend from an untrusted game folder or import historical schemas. Source-checkout regression: `node scripts/verify-registration-locator.mjs --dotnet /trusted/dotnet --compiler /trusted/csc.dll --framework /trusted/shared/Microsoft.NETCore.App/10.0.12 --out /work/NEW-fixture`.
