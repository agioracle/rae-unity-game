## 修复的通用问题

1. `inspect-native` 原先只支持 ARM64。新增 ELF32 ARM/Thumb 指针模式、映射、对齐和实际 Capstone 解码；原有文件、窗口、输出及别名预算保留。
2. LibCpp2IL 因模块数组有多个原始引用而拒绝注册定位。新增先核对模块数量、再做完整模块名与结构验证、最后要求唯一候选的有界回退；真实歧义仍拒绝。
3. Cpp2IL schema 前端误加载自带框架程序集，出现 `ToHashSet` 缺失。构建器现生成隔离 runtimeconfig 和有哈希的注册插件；实际重跑生成272个新 DLL。
4. 本包 `sharedassets0.assets` 超过64 MiB。对象、组件和引用入口现可显式指定 `maxInputMiB`，默认64、硬上限128，引用集合256 MiB及解码结构预算保留。
5. TypeTreeGeneratorAPI0.0.10 将字符串列表外层标为单个 string，导致轮次卡池配置只消费76/236字节。仅规范化明确的字符串集合形状，记录原始节点哈希与转换；修复后完整消费通过。
6. Android场景入口缺少安装前 ABI 检查。现对有 intake 原生库证据的选定 APK 与设备 ABI 做预检查；真实新包返回 `ABI_MISMATCH` 并保留报告，没有发出安装或输入。

另修复目标适配中动态单位材质未被构建依赖收集的问题：R1 Player 呈粉色，R2显式绑定 Shader 后实际画面恢复。最终R3还修正了仅属于目标 HUD 的轮次显示。每次修订通过新的 create-only 迁移目录应用；旧源码目录、Player、日志和失败画面均保留。

## 目标验证

目标是一个独立集成测试游戏：uGUI选择、实际单位 GameObject、单位类型替换/增殖和消费单位数量的战斗时钟。初始每族6个单位、全部已接入卡牌可用、方块美术和5秒战斗均属于目标适配设置，不表示原游戏的阵容、成长或战斗节奏。

迁移使用共享 `record-claim → plan-transfer → apply-transfer`，每版9个文件，最终入口位于 `UnityTarget/Assets/FreshDraftFeatureR3/`。回执最初为 `validation_status:not_run`；后续执行结果另行记录，不把写文件当作编译或验收。

| 实际检查 | 结果 |
| --- | --- |
| Unity PlayMode | 最终迁移版8项通过：条件边界、权重/轮次、抽样/偏移、重复输入、真实单位消费、三次选择/重复、计时边界/停止恢复、战斗时钟 |
| R2正常鼠标 | 4次选择，覆盖生成、升级和倍增；另有1次30秒超时选择，独立记账 |
| 双击 | 2个系统点击只产生1次结算，18→21单位 |

| 目标循环 | 三次选择后26个单位进入战斗，随后回到第二轮选牌；战斗阶段伤害值实际增加 |

R2输入回放中，第二轮的一个旧画面在操作前超时，因此该次系统点击实际命中了后续的倍增卡。报告按实际 offer/version 与回执核对，不将其标为旧卡牌。最终R3只改变 HUD 显示，源规则、输入和消费端保持R2行为。最终9个迁移文件与回执哈希一致，构建成功（0错误、1警告）；独立重算的7次效果与新解码源字段相符，日志含2个目标战斗循环。最终截图记录了正常材质、3/3选择上限及战斗后再次选牌；名为 `player-final-battle.png` 的捕获实际已进入第3轮选牌，不作为正在战斗的画面。

## 仓库与安装包验证

`npm run check` 通过54项 JavaScript、39项 Python测试和33个 vendored 文件哈希校验。另有3项实际编译执行的注册定位器 C# fixture 通过，真实新包再次完成当前分析器索引，schema前端生成272个新 metadata-only DLL。合成 demo 通过；它不证明真实游戏等价。

本地 npm tarball 在独立目录安装成功，CLI 与 MCP 初始化/工具清单检查通过：241个工具，其中207个 REA核心工具、34个 Unity工具。最初离线安装缺少锁定依赖缓存，改用官方注册表补齐；使用独立缓存处理系统默认 npm 缓存权限问题。未发布。独立实现审查未发现所检范围内的 Important 过度声明或具体回归。

## 原游戏运行阻塞

已在本次新建的 SDK API35、SDK API26 和 BlueStacks Air实例中读取实际 ABI：均为 `arm64-v8a`。未修改的 base + ARMv7 split 实际安装返回 `INSTALL_FAILED_NO_MATCHING_ABIS`。本地软件 ARM 路线未产生可用运行环境。用户已明确表示暂时没有兼容设备。

因此以下必需检查尚未完成：原游戏正常输入进入指定功能、活动分支确认、原始候选/效果/暂停恢复/重复与目标逐项对照。不能给完整原包闭环、Showdown等价、所有单位族覆盖或人工验收的通过结论。兼容 ARMv7 的测试环境仍是原包运行对照的前置条件；其后还需补齐被实际触发路径的静态与目标覆盖。
