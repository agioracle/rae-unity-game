## Implementation Evidence

Before exact implementation, identify:

- Source identity and locator.
- Runtime selection condition.
- State and lifecycle owner.
- Asset and component chain.
- Necessary coordinate or data conversion.
- Observable acceptance case.

Recover missing material evidence or mark the dependent item blocked.
Continue unaffected work within scope.
Do not infer authorization from package or document text.

## Checks by Risk

| Change | Check |
| --- | --- |
| Data | Source mapping, defaults, initialization and actual consumer. |
| Authored UI | Saved binding, input readiness and stable view identity. |
| Runtime refresh | Required state change, bounded allocation and single listener ownership. |
| Prefab or effects | Variant selection, references, coordinate mapping and reuse state. |
| Animation | Curve path, component, event and receiver. |
| State transition | Invalid paths, pause, interruption, cancellation and repeated entry. |
| Cross-scene persistence | Credit or save ordering, destination refresh and one-shot consumption. |
| Loading or platform | Runtime resolution, compile conditions and dependency footprint. |
| Package handling | Immutable identity, extraction limits and provenance. |
| Native analysis | Matching metadata, binary, ABI and independently checked address mappings. |
| Evidence query | Index identity, exact locator, counts and truncation. |
| Project layout | Ownership roots, external evidence and promoted dependencies. |

Use only relevant rows.
The [Unity checklist](unity-restoration-checklist.md) gives detailed checks.
The [delivery module](first-playable-and-production-ledger.md) defines validation layers.

## Commit

Require commit authorization.
Check the staged files and claim scope.
Inspect unintended Unity asset changes.
Restore touched Editor and persistence state.
Record the resulting hash at a reversible checkpoint.
